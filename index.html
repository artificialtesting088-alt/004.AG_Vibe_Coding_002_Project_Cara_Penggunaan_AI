01

RACE Framework

Framework 4 pilar untuk menulis prompt yang presisi dan menghasilkan output berkualitas tinggi.

R

Role

Siapa AI-nya?

+

Tentukan persona dan identitas AI. Role mengaktifkan pengetahuan domain spesifik, kosakata, dan perspektif profesional dalam model.

Tips

Spesifik soal keahlian dan senioritas, bukan sekadar jabatan generik. Hindari sanjungan berlebihan — fokus pada metodologi dan domain.

Contoh Role yang Efektif:

✅ "Kamu adalah Principal Backend Engineer yang spesialisasi 
   di sistem terdistribusi high-throughput menggunakan Go 
   dan PostgreSQL."

✅ "Kamu adalah konsultan data analytics dengan 15 tahun 
   pengalaman di industri e-commerce."

❌ "Kamu adalah programmer jenius terhebat di dunia."
   (Sanjungan tidak meningkatkan kualitas output)
A

Action

Apa tugasnya?

+

Instruksi spesifik dan tegas tentang apa yang harus dilakukan AI. Gunakan kata kerja yang kuat dan jelas — bukan permintaan yang ambigu.

Tips

Gunakan satu kata kerja utama yang decisive. Jika tugas kompleks, pecah menjadi langkah-langkah bernomor.

Contoh Action yang Efektif:

✅ "Refactor route handler Express berikut menjadi arsitektur 
   berlapis dengan validasi Zod dan caching Redis."

✅ "Lakukan gap analysis yang membandingkan checkout flow 
   kita dengan pattern friction-reduction milik Stripe."

❌ "Bantu saya dengan kode ini."
   (Terlalu ambigu — bantu bagaimana?)
C

Context

Apa konteksnya?

+

Berikan latar belakang, batasan, dan data yang dibutuhkan AI. Tanpa konteks, AI mengisi kekosongan dengan asumsi generik.

Tips

Gunakan "Tes Rekan Baru" — bayangkan kolega baru yang qualified bergabung hari ini, konteks apa yang dia butuhkan untuk menyelesaikan tugas tanpa bertanya 10 pertanyaan?

4 Elemen Context:

👥 Audience — Siapa pembacanya?
🏢 Environment — Tech stack, bisnis model?
📄 Input Data — Kode, log, data yang relevan
🎯 Situasi — Kenapa tugas ini penting sekarang?
E

Expectation

Apa yang diharapkan?

+

Definisikan format output, standar kualitas, dan kriteria sukses. Tanpa ekspektasi jelas, AI akan default ke output generik.

Tips

Sertakan juga "negative constraints" — hal yang TIDAK boleh ada. Contoh: "Jangan gunakan basa-basi pembuka", "Hindari jargon marketing".

Contoh Expectation yang Efektif:

✅ "Output dalam format tabel Markdown dengan 4 kolom:
   [Inisiatif | Target Metrik | Effort | Expected Lift].
   Maksimal 500 kata. Tanpa basa-basi."

✅ "Berikan kode TypeScript lengkap yang production-ready
   dengan error handling, JSDoc comments, dan unit test.
   Pastikan complexity O(n) dan lulus ESLint."

❌ "Buat yang bagus dan profesional."
   (Terlalu subjektif — bagus menurut siapa?)

💡 Contoh Prompt RACE Lengkap 

[ROLE]
Kamu adalah Staff Backend Engineer yang spesialisasi di 
Node.js, TypeScript, dan microservice resilience.

[ACTION]
Refactor route handler Express berikut menjadi arsitektur 
berlapis (Controller → Service → Repository) dengan validasi 
schema, distributed caching, dan defensive error handling.

[CONTEXT]
Kami menjalankan platform e-commerce flash-sale dengan traffic 
tinggi. Endpoint /products/:id saat ini query PostgreSQL 
langsung di setiap hit, menyebabkan connection pool exhaustion 
saat surge traffic.
Stack: Node.js 20, Express, TypeScript, Zod, ioredis, pg-promise.

Kode legacy saat ini:
```typescript
app.get('/products/:id', async (req, res) => {
  try {
    const product = await db.query(
      'SELECT * FROM products WHERE id = ' + req.params.id
    );
    res.json(product);
  } catch (err) {
    res.status(500).send('Error');
  }
});
```

[EXPECTATION]
1. Kode TypeScript lengkap terpisah per layer (Controller, 
   Service, Repository).
2. Validasi input dengan Zod + error response HTTP 400.
3. Cache-Aside pattern dengan Redis TTL 60 detik + graceful 
   degradation jika Redis down.
4. Parameterized queries untuk eliminasi SQL injection.
5. Ringkasan 4 poin peningkatan security & performance.
[ROLE]
Kamu adalah VP Customer Success dan Executive Communications 
di perusahaan SaaS B2B enterprise.

[ACTION]
Draft email notifikasi insiden layanan yang empatik, transparan, 
dan otoritatif untuk dikirim ke pelanggan Enterprise Fortune 500.

[CONTEXT]
Platform kolaborasi dokumen cloud kami mengalami outage global 
47 menit hari ini antara 14:15-15:02 UTC akibat konfigurasi 
BGP routing table yang salah dari upstream transit provider. 
Pelanggan mengalami 502 Gateway Errors dan tidak bisa mengakses 
kontrak yang sudah ditandatangani selama window end-of-quarter. 
Layanan sudah dipulihkan sepenuhnya. Zero data compromised.

[EXPECTATION]
1. Subject line profesional, langsung, tanpa sensasionalisme.
2. Struktur 4 bagian: (a) Status & acknowledgment dampak bisnis,
   (b) Root cause dalam bahasa teknis yang jelas, non-defensif,
   (c) Langkah preventif yang sudah diimplementasi,
   (d) Pathway klaim SLA credit + kontak langsung.
3. Tone: Accountable, calm, enterprise-grade. Tanpa excuse.
4. Panjang: 200-300 kata.
[ROLE]
Kamu adalah Principal Product Analytics Consultant yang 
spesialisasi di SaaS subscription economics dan retention modeling.

[ACTION]
Analisis dataset cohort retention month-over-month berikut, 
diagnosis inflection point churn, dan rekomendasikan 3 intervensi 
produk berdampak tinggi.

[CONTEXT]
Kami menjalankan SaaS project management B2B dengan free trial 
14 hari → $49/seat/bulan.
Data Cohort:
- Month 0 (Signup): 100% aktif (Avg. 1.200 akun/bulan)
- Month 1: 82% retention
- Month 2: 74% retention  
- Month 3: 41% retention ← CLIFF TAJAM
- Month 4: 39% retention
- Month 5: 38% retention
Telemetri menunjukkan drop-off setelah billing cycle kuartal 
pertama atau setelah milestone proyek selesai.

[EXPECTATION]
Format Executive Brief dengan header Markdown:
1. Root Cause Diagnosis — kenapa drop M2→M3 terjadi
2. Comparative Benchmark — vs top-quartile B2B SaaS
3. Actionable Interventions — tabel Markdown: [Inisiatif | 
   Target Metrik | Effort (Low/Med/High) | Expected Lift (%)]
4. Tanpa saran generik seperti "tingkatkan customer service".
[ROLE]
Kamu adalah Lead Product Designer dan Design Systems Architect 
yang spesialisasi di mobile fintech dan UX regulasi KYC/AML.

[ACTION]
Rancang user flow onboarding dan verifikasi identitas mobile 
yang intuitif, low-friction, dan memenuhi standar compliance.

[CONTEXT]
Kami meluncurkan aplikasi micro-investment lintas negara untuk 
Gen Z (iOS & Android). Testing saat ini menunjukkan 68% 
abandonment rate di screen upload KTP dan bukti alamat.
User mengeluh app terasa "intimidating" dan meminta terlalu 
banyak data pribadi sebelum menunjukkan value produk.

[EXPECTATION]
1. Step-by-Step User Flow — breakdown screen-per-screen dengan 
   prinsip progressive disclosure.
2. Friction Mitigation UX Patterns — komponen UI untuk trust 
   (microcopy kontekstual, biometric fallback, progress tracking).
3. Error Handling States — handle camera permission denial dan 
   unreadable document tanpa restart seluruh sequence.
4. Sertakan diagram Mermaid flowchart (flowchart TD).
5. Grounded di Apple HIG dan Material You guidelines.
[ROLE]
Kamu adalah Senior Site Reliability Engineer (SRE) dan 
Post-Incident Review Lead.

[ACTION]
Lakukan 5-Whys Root Cause Analysis (RCA) terhadap data log 
insiden berikut, identifikasi vulnerability arsitektural 
sistemik, dan buat backlog remediasi.

[CONTEXT]
Insiden: Jumat 19:30 UTC, payment processing engine berhenti 
memproses otorisasi kartu — cascade 504 Timeout selama 32 menit.
Telemetri:
- Connection pool orders_db 100% saturated
- Deadlock antara process_recurring_subscriptions (batch) dan 
  process_live_checkout (real-time row locks)
- Thread dump: ratusan worker WAITING pada row-level table locks

[EXPECTATION]
1. 5-Whys Analysis — rantai kausal 5 level yang jelas.
2. Systemic Architectural Flaw — paragraf singkat tentang 
   lock ordering anti-pattern.
3. Remediation Plan terstruktur:
   - P0 (Hotfix immediate 24h)
   - P1 (Architectural refactor sprint ini)
   - P2 (Monitoring, alerting, chaos engineering)
4. Standar blameless post-mortem Google SRE.

⚠️ Kesalahan Umum RACE Framework

01

Flattery Fallacy

Memuji AI berlebihan ("jenius terhebat") tidak meningkatkan kualitas. Fokus pada domain dan metodologi.

02

Action Bloat

Menggabungkan terlalu banyak tugas dalam satu prompt. Pecah menjadi beberapa prompt fokus.

03

Context Starvation

Mengasumsikan AI tahu arsitektur internal Anda. Berikan konteks yang cukup — tapi jangan dump data.

04

Ekspektasi Ambigu

"Buat yang bagus" bukan ekspektasi. Definisikan format, panjang, tone, dan batasan negatif.

05

Fire-and-Forget

Mengharapkan hasil sempurna dari prompt pertama. RACE adalah fondasi — iterasi untuk menyempurnakan.

06

Tanpa Delimiter

Mencampur instruksi dengan data input tanpa pemisah. Gunakan header atau tag XML yang jelas.

02

Context Engineering

Lebih dari sekadar prompt — ini tentang merancang seluruh ekosistem informasi untuk AI.

Prompt Engineering vs Context Engineering

Dimensi Prompt Engineering Context Engineering
Fokus Cara menyusun instruksi (kata-kata, tone, persona) Seluruh lingkungan data di sekitar model (retrieval, history, tools)
Sifat Statis — template tunggal Dinamis — berubah saat runtime berdasarkan tugas
Cakupan Mikro — "wordsmithing" per prompt Makro — arsitektur sistem (caching, routing, retrieval)
Analogi Menulis pertanyaan interview yang baik Menyiapkan seluruh briefing packet untuk interviewer
Artefak Template prompt, few-shot examples Pipeline RAG, memory tiers, MCP connections, cache policies

5 Pilar Context Engineering

📦

Context Window Management

Strategi alokasi token: bagaimana membagi context window antara system rules, tool schemas, RAG data, conversation history, dan output reserve.

Kunci: Attention transformer tidak seragam — token di awal (primacy) dan akhir (recency) mendapat perhatian lebih. Tempatkan instruksi kritis di posisi ini.

🔍

Retrieval Augmented Generation

Mengambil dokumen relevan dari knowledge base eksternal sebelum generate response, lalu inject ke context window.

Kunci: Gunakan hybrid search (dense + sparse), two-stage retrieval dengan reranking, dan semantic-aware chunking.

🧠

Memory Systems

Memberikan AI kemampuan mengingat informasi lintas sesi — dari short-term hingga long-term memory.

4 Tipe: Working Memory (in-context), Episodic (event history), Semantic (factual knowledge), Procedural (workflow SOPs).

🛠️

Tool Use

Memberi AI kemampuan memanggil tools eksternal — API, database, code interpreter, web search, file system.

Kunci: Tool definition yang jelas (nama, deskripsi, schema), error handling yang graceful, dan permission control.

📋

Structured Context

Memberikan context dalam format terstruktur — bukan blob teks acak. AI memparse teks terstruktur dengan variansi jauh lebih rendah.

Kunci: Gunakan XML tags, Markdown headers, JSON/YAML schema, dan pemisah semantik yang jelas.

Teknik Context Engineering Lanjutan

🗜️ Context Compression

Kurangi token tanpa kehilangan makna: summarization, key-value extraction, perplexity pruning (LLMLingua), dan trajectory compaction untuk agent loop.

🏗️ Hierarchical Context

Susun context berlapis: System Prompt → User Profile → Task Context → Retrieved Data → Conversation History → Tool Results. Setiap layer makin spesifik.

🎯 Dynamic Context Selection

Otomatis pilih context berdasarkan tugas: JIT (Just-In-Time) context ingestion, semantic gating, dan KV-cache pruning. Inject hanya saat dibutuhkan.

🔄 Context Caching

Urutan context dari volatilitas terendah ke tertinggi: static system rules → tool schemas → reference docs → dynamic conversation. Ini memaksimalkan provider prompt caching.

📐 Contoh Structured Context

<role>
Kamu adalah customer support agent untuk Acme Corp.
</role>

<guidelines>
- Selalu sopan dan empatik.
- Jangan pernah bagikan data internal perusahaan.
- Jika tidak tahu jawabannya, katakan dengan jujur.
</guidelines>

<knowledge_base>
[Dokumen yang diambil dari database tentang produk customer]
</knowledge_base>

<customer_profile>
Nama: Budi Santoso
Plan: Enterprise
Member sejak: 2022
Issue terakhir: Login problem (resolved 2025-01-15)
</customer_profile>

<instructions>
Berdasarkan profil dan knowledge base di atas, jawab 
pertanyaan customer berikut secara personal dan helpful.
Pertanyaan: {{user_query}}
</instructions>

Teknik Prompting Lanjutan

Chain of Thought, Few-Shot Learning, dan System Prompt — teknik yang membedakan pengguna AI biasa dari yang mahir.

Chain of Thought (CoT) Prompting

Teknik yang menginstruksikan AI untuk "berpikir langkah demi langkah" sebelum memberikan jawaban akhir. Ini memaksa model memecah masalah kompleks menjadi langkah reasoning berurutan.

Zero-Shot CoT

Cukup tambahkan "Pikirkan langkah demi langkah" — tanpa contoh.

Selesaikan masalah ini. Pikirkan langkah demi langkah.

Toko menjual apel Rp5.000/buah dan jeruk Rp8.000/buah.
Jika saya beli 5 apel dan 3 jeruk, lalu punya kupon 
diskon 10%, berapa yang harus saya bayar?

Few-Shot CoT

Berikan contoh reasoning step-by-step sebelum masalah sebenarnya.

Tree of Thoughts (ToT)

Generalisasi CoT menjadi tree search — explore beberapa jalur reasoning, evaluasi, pilih yang terbaik.

ReAct (Reasoning + Acting)

Interleaving langkah berpikir dan bertindak:

Thought → Action → Observation → Thought → Final Answer

Few-Shot vs Zero-Shot Prompting

Zero-Shot

Definisi: Instruksi langsung tanpa contoh input/output.

Kapan pakai: Tugas umum, creative writing, task yang model sudah "tahu".

Kelebihan: Hemat token, cepat, tanpa risiko bias contoh.

Terjemahkan "Selamat pagi, apa kabar?" ke bahasa Jepang.
Few-Shot

Definisi: Berikan 1-5 contoh pola input/output sebelum tugas sebenarnya.

Kapan pakai: Format custom, domain spesifik, konsistensi output.

Kelebihan: Konsistensi luar biasa, handle edge case.

Klasifikasikan sentimen review berikut:

Review: "Makanannya luar biasa enak!"
Sentimen: Positif

Review: "Pelayanan buruk, tunggu 45 menit."
Sentimen: Negatif

Review: "Biasa saja, tidak ada yang istimewa."
Sentimen: Netral

Review: "Pengalaman terbaik yang pernah saya alami!"
Sentimen:

Tips Memilih Exemplar:

  • Diversitas > Volume: 3 contoh diverse yang cover edge case lebih baik dari 10 contoh seragam.
  • Urutan penting: LLM punya recency bias — taruh contoh paling representatif tepat sebelum prompt sebenarnya.
  • Distribusi seimbang: Untuk klasifikasi, pastikan setiap kelas terwakili rata.

Struktur System Prompt yang Optimal

System prompt adalah "konstitusi" AI — mendefinisikan identitas, batasan operasional, dan standar output.

# 1. ROLE & IDENTITY
Kamu adalah expert Security Engineer Assistant yang 
spesialisasi di static application security testing (SAST).

# 2. CORE CAPABILITIES & TOOLS
Kamu punya akses ke search, file reading, dan bash execution.
Gunakan tools untuk investigasi codebase sebelum menjawab.

# 3. OPERATIONAL WORKFLOW
1. Analisis inquiry user.
2. Inspeksi file repository yang relevan.
3. Identifikasi vulnerability terhadap OWASP Top 10.
4. Usulkan remediation patch dengan penjelasan.

# 4. CONSTRAINTS & GUARDRAILS
- JANGAN execute command yang modify git history tanpa 
  konfirmasi.
- Jika vulnerability uncertain, nyatakan confidence level.
- JANGAN PERNAH membuat-buat library version atau API 
  parameter.

# 5. OUTPUT FORMAT
Return semua vulnerability assessment dalam JSON schema:
```json
{
  "cwe_id": "string",
  "severity": "LOW | MEDIUM | HIGH | CRITICAL",
  "file": "string",
  "line": "number",
  "remediation": "string"
}
```

Aturan Kunci System Prompt:

1

Positive + Negative: Nyatakan apa yang harus dilakukan, diikuti larangan eksplisit (JANGAN, TIDAK BOLEH).

2

Handle Ambiguitas: Instruksikan: "Jika konteks tidak cukup, katakan 'Saya tidak punya informasi yang cukup'."

3

Delimiter Tags: Gunakan XML tags untuk pisahkan instruksi, system data, dan user input.

4

Version Control: Perlakukan system prompt seperti production code — version, test, deploy.

AI Connectors & MCP

Connectors menghubungkan AI ke dunia luar — database, API, file system, dan layanan cloud. MCP menstandardisasi semuanya.

Connector memberikan AI tiga kemampuan kritis:

👁️

Perception

Inspect database, baca file, fetch web pages, observasi sistem metrik

⚡

Actionability

Trigger workflow, kirim pesan, commit kode, invoke external API

🎯

Grounding

Akses data enterprise privat dan real-time untuk eliminasi halusinasi

Jenis-Jenis Connector

🔌

MCP Servers

Protokol standar terbuka untuk komunikasi agent-to-tool. JSON-RPC 2.0 via stdio atau SSE.

🌐

API Connectors

REST, GraphQL, gRPC — wrapper yang mengkonversi JSON function-calling ke HTTP requests.

🧩

Plugins & Extensions

Integrasi platform-specific: ChatGPT Actions, Copilot plugins, VS Code extensions.

💾

Database Connectors

SQL (PostgreSQL, MySQL), NoSQL (MongoDB), Vector DB (Pinecone, Qdrant) untuk RAG.

📁

File System

Baca/tulis file lokal, cloud storage (S3, Google Drive), parsing dokumen (PDF, DOCX).

💬

Communication

Slack, Teams, Discord, Email — kirim notifikasi, search channel history, post updates.

🔌 Model Context Protocol (MCP) — Deep Dive

"USB-C untuk Aplikasi AI" — standar universal yang menghubungkan AI model mana pun ke tool mana pun.

MCP Host Claude, VS Code, Cursor, Antigravity
↔
MCP Client Maintains connections
↔
MCP Server Exposes Tools, Resources, Prompts
📄 Resources

Client/App Controlled — Data read-only yang di-inject ke prompt (file contents, database schemas, logs).

🛠️ Tools

Model Controlled — Fungsi yang bisa dipanggil LLM. Model memutuskan kapan dan dengan argumen apa.

📝 Prompts

User Controlled — Template prompt yang bisa di-trigger user untuk memulai tugas terstruktur.

Best Practices Connector

01

Principle of Least Privilege

Batasi database connector ke read-only. Minta konfirmasi manusia sebelum aksi destruktif.

02

Schema Minimization

50+ tool schema sekaligus menurunkan reasoning model. Gunakan dynamic tool filtering.

03

Idempotency

Tool yang mutate state harus accept idempotency key atau pre-flight check.

04

Resilience

Implement rate limiter dan exponential backoff. Return error string yang informatif.

06

Parameter Tuning

Temperature, Top-P, Frequency Penalty — parameter yang membentuk distribusi probabilitas token dan menentukan karakter output AI.

🌡️ Temperature — Mengontrol Randomness

0.0 Deterministic
0.3 Focused
0.7 Balanced
1.0 Creative
2.0 Chaotic

📊 Rekomendasi Parameter per Use Case

Use Case Temperature Top-P Freq Penalty Rationale
💻 Code Generation 0.0 - 0.2 0.9 0.0 Eliminasi syntax hallucination, maksimalkan determinisme
📋 Data Extraction / JSON 0.0 1.0 0.0 Strict schema adherence, predictability absolut
🔍 Analisis / Root Cause 0.2 - 0.3 0.95 0.1 Presisi faktual tinggi dengan transisi logis yang smooth
✍️ Technical Writing 0.5 - 0.7 0.9 0.2 Prosa fluent dan profesional tanpa phrasing aneh
🎨 Brainstorming / Creative 0.8 - 1.1 0.95 0.4 Variansi tinggi, vocabulary diverse, metafora novel

Parameter Lainnya

Top-P (Nucleus Sampling)

Sampling hanya dari token terkecil yang probabilitas kumulatifnya melebihi threshold P. Adaptif secara kontekstual — saat confidence tinggi, hanya 1-2 token dipertimbangkan.

Range: 0.0 - 1.0 | Default: 0.9

Presence Penalty

Penalti pada token yang sudah muncul setidaknya sekali. Mendorong model membahas topik baru dan menghindari pengulangan.

Range: -2.0 - 2.0 | Default: 0.0

Frequency Penalty

Penalti proporsional terhadap frekuensi kemunculan token. Semakin sering muncul, semakin besar penalti — mencegah loop dan repetisi.

Range: -2.0 - 2.0 | Default: 0.0

Max Tokens

Batas maksimum panjang response. Berguna untuk mengontrol output length dan biaya. Tidak mempengaruhi kualitas reasoning.

Range: 1 - model limit

Ringkasan — 5 Kunci Menguasai AI

01

Gunakan RACE Framework — Structure setiap prompt dengan Role, Action, Context, Expectation.

02

Engineer Context, bukan hanya Prompt — Rancang seluruh ekosistem informasi di sekitar model.

03
