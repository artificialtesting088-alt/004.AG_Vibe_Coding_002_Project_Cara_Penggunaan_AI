Context Engineering & Anatomi Context Window

Prompt Engineering hanyalah permulaan. Context Engineering adalah seni dan sains merancang seluruh ekosistem informasi yang masuk ke dalam memori LLM.

⏱️ Waktu baca: ~12 menit
🧠 Tingkat: Menengah–Lanjutan
📦 7 Komponen Context Window
⚡ Visual RAM Stack Buffer

Prompt Engineering vs Context Engineering

Dimensi Prompt Engineering Context Engineering
Fokus Cara menyusun instruksi (kata-kata, tone, persona) Seluruh lingkungan data di sekitar model (retrieval, history, tools)
Sifat Statis — template tunggal Dinamis — berubah saat runtime berdasarkan tugas
Cakupan Mikro — "wordsmithing" per prompt Makro — arsitektur sistem (caching, routing, retrieval)
Analogi Menulis pertanyaan interview yang baik Menyiapkan seluruh briefing packet untuk interviewer
Artefak Template prompt, few-shot examples Pipeline RAG, memory tiers, MCP connections, cache policies

🧩 Anatomi Context Window: Apa Saja yang Dimasukkan ke AI?

Banyak orang mengira AI hanya membaca "prompt" yang kita ketik. Faktanya, dalam Context Engineering, apa yang dilihat oleh model AI adalah seluruh ruang kerja informasi (Context Window) yang diracik secara dinamis dari 7 komponen utama sebelum model memprediksi satu token pun:

Lapisan 1

🏛️ System Prompt & Instructions

Konstitusi permanen: aturan perilaku, persona keahlian, guardrails keamanan, & format output wajib.

Statis / Cached
Lapisan 2

🛠️ Tools & Skills Definition (SOP & Schemas)

Kamus fungsi yang bisa dipanggil AI (JSON schema API, SQL, Bash) + panduan prosedur kerja (SKILL.md).

Tool Catalog
Lapisan 3

📚 Dokumen Eksternal & Knowledge Base (RAG)

Cuplikan berkas kode, file PDF, data database, atau artikel internal relevan yang di-retrieve secara otomatis.

Retrieved Data
Lapisan 4

⏳ Memory & Riwayat Percakapan (Conversation History)

Buffer dialog sebelumnya (sliding window) + ringkasan turn lampau agar AI tidak kehilangan memori konteks.

Multi-Turn Context
Lapisan 5

📝 Scratchpad / Working Memory (Catatan Berpikir AI)

Rencana langkah (step-by-step plan), jejak pemikiran (Chain of Thought), & pelacakan status tugas aktif.

Agent State
Lapisan 6

⚡ Tool Execution Results / Observations

Output nyata dari tools yang baru dijalankan: log error terminal, baris data query SQL, respons API JSON.

Live Observation
Lapisan 7

💬 User Prompt (Instruksi / Query Utama Saat Ini)

Pertanyaan atau perintah baru yang Anda ketik di kolom pesan/chat saat ini.

Active Input
🏛️

1. System Prompt

Aturan & Persona

Konstitusi model. Menentukan batas wewenang, tone profesional, larangan keras (negative constraints), dan format JSON/Markdown yang diharapkan.

Contoh: "Kamu adalah Senior Database Admin. Jangan pernah drop table. Format jawaban selalu berupa tabel DDL..."
🛠️

2. Skills & Tool Schemas

Kemampuan Eksekusi

Bukan sekadar teks bebas, melainkan spesifikasi teknis fungsi yang bisa dieksekusi (JSON schema) dan SOP kerja (SKILL.md) agar model tahu tool apa yang cocok.

Contoh: {"name": "query_postgres", "parameters": {"sql": "SELECT ..."}, "description": "Eksekusi read-only query"}
📂

3. Dokumen & RAG Data

Pengetahuan Grounding

Potongan dokumen eksternal yang di-inject ke context window saat runtime: repositori kode, artikel FAQ, manual PDF, atau catatan meeting.

Contoh: File schema.prisma atau kebijakan retur produk 2025 yang diambil dari vector database.
💬

4. User Prompt

Tugas Utama

Pemicu aksi saat ini yang diketik oleh pengguna. Disusun menggunakan framework presisi seperti RACE (Role, Action, Context, Expectation).

Contoh: "Refactor fungsi autentikasi berikut agar menggunakan token JWT dengan rotasi kunci..."
⏳

5. Riwayat Percakapan

Memori Dialog

Percakapan multi-turn sebelumnya. Karena LLM bersifat stateless, riwayat ini harus dipasok kembali (atau diringkas) agar AI nyambung dengan konteks lalu.

Contoh: "Turn 1: User minta skema DB -> Model beri DDL -> Turn 2: User: 'Tambahkan foreign key user_id'..."
🧠

6. Scratchpad / State

Jejak Penalaran

Working memory tempat model merencanakan tindakan (*plan*), merefleksikan kegagalan, dan mencatat checklist langkah yang belum selesai.

Contoh: "Langkah 1 selesai: file auth.ts dibaca. Langkah 2: import bcrypt belum ada, saya harus menambahkan..."
⚡

7. Hasil Eksekusi Tools

Hasil Observasi Live

Keluaran nyata dari lingkungan eksternal setelah tool dijalankan: error code terminal, respons HTTP status 200, atau log error yang harus di-triage.

Contoh: [Tool Output: bash] Error: TypeError: Cannot read properties of undefined (reading 'token') at line 42

5 Pilar Context Engineering

📦

Context Window Management

Strategi alokasi token: bagaimana membagi context window antara system rules, tool schemas, RAG data, conversation history, dan output reserve.

Kunci: Attention transformer tidak seragam — token di awal (primacy) dan akhir (recency) mendapat perhatian lebih. Tempatkan instruksi kritis di posisi ini.

🔍

Retrieval Augmented Generation

Mengambil dokumen relevan dari knowledge base eksternal sebelum generate response, lalu inject ke context window.

Kunci: Gunakan hybrid search (dense + sparse), two-stage retrieval dengan reranking, dan semantic-aware chunking.

🧠

Memory Systems

Memberikan AI kemampuan mengingat informasi lintas sesi — dari short-term hingga long-term memory.

4 Tipe: Working Memory (in-context), Episodic (event history), Semantic (factual knowledge), Procedural (workflow SOPs).

🛠️

Tool Use

Memberi AI kemampuan memanggil tools eksternal — API, database, code interpreter, web search, file system.

Kunci: Tool definition yang jelas (nama, deskripsi, schema), error handling yang graceful, dan permission control.

📋

Structured Context

Memberikan context dalam format terstruktur — bukan blob teks acak. AI memparse teks terstruktur dengan variansi jauh lebih rendah.

Kunci: Gunakan XML tags, Markdown headers, JSON/YAML schema, dan pemisah semantik yang jelas.

Teknik Context Engineering Lanjutan

🗜️ Context Compression

Kurangi token tanpa kehilangan makna: summarization, key-value extraction, perplexity pruning (LLMLingua), dan trajectory compaction untuk agent loop.

🏗️ Hierarchical Context

Susun context berlapis: System Prompt → User Profile → Task Context → Retrieved Data → Conversation History → Tool Results. Setiap layer makin spesifik.

🎯 Dynamic Context Selection

Otomatis pilih context berdasarkan tugas: JIT (Just-In-Time) context ingestion, semantic gating, dan KV-cache pruning. Inject hanya saat dibutuhkan.

🔄 Context Caching

Urutan context dari volatilitas terendah ke tertinggi: static system rules → tool schemas → reference docs → dynamic conversation. Ini memaksimalkan provider prompt caching.

📐 Contoh Structured Context

<role>
Kamu adalah customer support agent untuk Acme Corp.
</role>

<guidelines>
- Selalu sopan dan empatik.
- Jangan pernah bagikan data internal perusahaan.
- Jika tidak tahu jawabannya, katakan dengan jujur.
</guidelines>

<knowledge_base>
[Dokumen yang diambil dari database tentang produk customer]
</knowledge_base>

<customer_profile>
Nama: Budi Santoso
Plan: Enterprise
Member sejak: 2022
Issue terakhir: Login problem (resolved 2025-01-15)
</customer_profile>

<instructions>
Berdasarkan profil dan knowledge base di atas, jawab 
pertanyaan customer berikut secara personal dan helpful.
Pertanyaan: {{user_query}}
</instructions>

Ringkasan — 5 Kunci Menguasai AI

01

Gunakan RACE Framework — Structure setiap prompt dengan Role, Action, Context, Expectation.

02

Engineer Context, bukan hanya Prompt — Rancang seluruh ekosistem informasi di sekitar model.

03

Kuasai teknik lanjutan — Chain of Thought, Few-Shot, dan System Prompt yang terstruktur.

04

Leverage Skills & Connectors — Kombinasikan skills modular dan hubungkan AI ke tools via MCP.

05

Tune parameter sesuai tugas — Low temperature untuk kode, tinggi untuk brainstorming.
