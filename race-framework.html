MODUL 01 • PROMPT ENGINEERING

RACE Framework untuk Prompt Engineering

Formula 4 pilar terstruktur untuk mengubah prompt amatir menjadi instruksi presisi tingkat industri tanpa ambiguitas.

⏱️ Waktu baca: ~8 menit
🎯 Tingkat: Fundamental
💡 5 Contoh Prompt Interaktif
📊 2x2 Spacious Cards
R

Role

Siapa AI-nya?

Kondisikan persona, domain prior, & tingkat senioritas profesional model

Role mengaktifkan kluster pengetahuan spesifik, kosakata industri, dan cara berpikir pakar domain di dalam model AI.

Tips Pro

Sebutkan domain dan metodologi spesifik (misal: "Principal Backend Engineer"), bukan sanjungan kosong ("programmer terhebat").

Contoh Implementasi Prompt:

✅ "Kamu adalah Principal Backend Engineer yang spesialisasi di sistem terdistribusi high-throughput menggunakan Go dan PostgreSQL."

✅ "Kamu adalah konsultan data analytics dengan 15 tahun pengalaman di industri e-commerce."

❌ "Kamu adalah programmer jenius terhebat di dunia." (Sanjungan tidak menaikkan kualitas output)
A

Action

Apa tugasnya?

Instruksi kata kerja operasional yang decisive, presisi, dan terukur

Gunakan kata kerja kuat yang memperjelas tugas akhir. Hindari instruksi ambigu yang memaksa AI menebak maksud Anda.

Tips Pro

Gunakan satu kata kerja tindakan utama. Jika tugas kompleks, pecah menjadi langkah bernomor 1, 2, 3.

Contoh Implementasi Prompt:

✅ "Refactor route handler Express berikut menjadi arsitektur berlapis dengan validasi Zod dan caching Redis."

✅ "Lakukan gap analysis yang membandingkan checkout flow kita dengan pattern friction-reduction milik Stripe."

❌ "Bantu saya dengan kode ini." (Terlalu ambigu — bantu dalam hal apa?)
C

Context

Apa konteksnya?

Latar belakang teknis, batasan bisnis, target pembaca, dan data input

Tanpa konteks, AI akan mengisi kekosongan dengan asumsi umum yang belum tentu cocok untuk kasus spesifik Anda.

Tips Pro

Terapkan "Tes Rekan Baru": informasi apa yang wajib diketahui rekan kerja baru agar tugas ini selesai tanpa banyak bertanya?

4 Elemen Konteks Wajib:

👥
Audience: Siapa pembaca / target pengguna akhir?
🏢
Environment: Tech stack, skala traffic, aturan bisnis?
📄
Input Data: Cuplikan kode, skema JSON, log telemetri?
🎯
Situasi: Mengapa tugas ini krusial diselesaikan sekarang?
E

Expectation

Apa yang diharapkan?

Format output spesifik, kriteria evaluasi kualitas, & batasan negatif

Kunci eliminasi output generik: tentukan format (tabel, JSON, bullet), panjang maksimal, serta apa yang TIDAK boleh ada.

Tips Pro

Selalu sertakan Negative Constraints, misal: "Tanpa basa-basi pembuka", "Jangan gunakan library pihak ketiga".

Contoh Implementasi Prompt:

✅ "Output berupa tabel Markdown 4 kolom: [Inisiatif | Target Metrik | Effort | Expected Lift]. Maksimal 500 kata. Tanpa basa-basi pembuka."

✅ "Berikan kode TypeScript production-ready dengan error handling, JSDoc, dan unit test Vitest. Complexity O(n)."

❌ "Buat yang bagus dan profesional." (Terlalu subjektif dan tidak terukur)

💡 Contoh Prompt RACE Lengkap 

[ROLE]
Kamu adalah Staff Backend Engineer yang spesialisasi di 
Node.js, TypeScript, dan microservice resilience.

[ACTION]
Refactor route handler Express berikut menjadi arsitektur 
berlapis (Controller → Service → Repository) dengan validasi 
schema, distributed caching, dan defensive error handling.

[CONTEXT]
Kami menjalankan platform e-commerce flash-sale dengan traffic 
tinggi. Endpoint /products/:id saat ini query PostgreSQL 
langsung di setiap hit, menyebabkan connection pool exhaustion 
saat surge traffic.
Stack: Node.js 20, Express, TypeScript, Zod, ioredis, pg-promise.

Kode legacy saat ini:
```typescript
app.get('/products/:id', async (req, res) => {
  try {
    const product = await db.query(
      'SELECT * FROM products WHERE id = ' + req.params.id
    );
    res.json(product);
  } catch (err) {
    res.status(500).send('Error');
  }
});
```

[EXPECTATION]
1. Kode TypeScript lengkap terpisah per layer (Controller, 
   Service, Repository).
2. Validasi input dengan Zod + error response HTTP 400.
3. Cache-Aside pattern dengan Redis TTL 60 detik + graceful 
   degradation jika Redis down.
4. Parameterized queries untuk eliminasi SQL injection.
5. Ringkasan 4 poin peningkatan security & performance.
[ROLE]
Kamu adalah VP Customer Success dan Executive Communications 
di perusahaan SaaS B2B enterprise.

[ACTION]
Draft email notifikasi insiden layanan yang empatik, transparan, 
dan otoritatif untuk dikirim ke pelanggan Enterprise Fortune 500.

[CONTEXT]
Platform kolaborasi dokumen cloud kami mengalami outage global 
47 menit hari ini antara 14:15-15:02 UTC akibat konfigurasi 
BGP routing table yang salah dari upstream transit provider. 
Pelanggan mengalami 502 Gateway Errors dan tidak bisa mengakses 
kontrak yang sudah ditandatangani selama window end-of-quarter. 
Layanan sudah dipulihkan sepenuhnya. Zero data compromised.

[EXPECTATION]
1. Subject line profesional, langsung, tanpa sensasionalisme.
2. Struktur 4 bagian: (a) Status & acknowledgment dampak bisnis,
   (b) Root cause dalam bahasa teknis yang jelas, non-defensif,
   (c) Langkah preventif yang sudah diimplementasi,
   (d) Pathway klaim SLA credit + kontak langsung.
3. Tone: Accountable, calm, enterprise-grade. Tanpa excuse.
4. Panjang: 200-300 kata.
[ROLE]
Kamu adalah Principal Product Analytics Consultant yang 
spesialisasi di SaaS subscription economics dan retention modeling.

[ACTION]
Analisis dataset cohort retention month-over-month berikut, 
diagnosis inflection point churn, dan rekomendasikan 3 intervensi 
produk berdampak tinggi.

[CONTEXT]
Kami menjalankan SaaS project management B2B dengan free trial 
14 hari → $49/seat/bulan.
Data Cohort:
- Month 0 (Signup): 100% aktif (Avg. 1.200 akun/bulan)
- Month 1: 82% retention
- Month 2: 74% retention  
- Month 3: 41% retention ← CLIFF TAJAM
- Month 4: 39% retention
- Month 5: 38% retention
Telemetri menunjukkan drop-off setelah billing cycle kuartal 
pertama atau setelah milestone proyek selesai.

[EXPECTATION]
Format Executive Brief dengan header Markdown:
1. Root Cause Diagnosis — kenapa drop M2→M3 terjadi
2. Comparative Benchmark — vs top-quartile B2B SaaS
3. Actionable Interventions — tabel Markdown: [Inisiatif | 
   Target Metrik | Effort (Low/Med/High) | Expected Lift (%)]
4. Tanpa saran generik seperti "tingkatkan customer service".
[ROLE]
Kamu adalah Lead Product Designer dan Design Systems Architect 
yang spesialisasi di mobile fintech dan UX regulasi KYC/AML.

[ACTION]
Rancang user flow onboarding dan verifikasi identitas mobile 
yang intuitif, low-friction, dan memenuhi standar compliance.

[CONTEXT]
Kami meluncurkan aplikasi micro-investment lintas negara untuk 
Gen Z (iOS & Android). Testing saat ini menunjukkan 68% 
abandonment rate di screen upload KTP dan bukti alamat.
User mengeluh app terasa "intimidating" dan meminta terlalu 
banyak data pribadi sebelum menunjukkan value produk.

[EXPECTATION]
1. Step-by-Step User Flow — breakdown screen-per-screen dengan 
   prinsip progressive disclosure.
2. Friction Mitigation UX Patterns — komponen UI untuk trust 
   (microcopy kontekstual, biometric fallback, progress tracking).
3. Error Handling States — handle camera permission denial dan 
   unreadable document tanpa restart seluruh sequence.
4. Sertakan diagram Mermaid flowchart (flowchart TD).
5. Grounded di Apple HIG dan Material You guidelines.
[ROLE]
Kamu adalah Senior Site Reliability Engineer (SRE) dan 
Post-Incident Review Lead.

[ACTION]
Lakukan 5-Whys Root Cause Analysis (RCA) terhadap data log 
insiden berikut, identifikasi vulnerability arsitektural 
sistemik, dan buat backlog remediasi.

[CONTEXT]
Insiden: Jumat 19:30 UTC, payment processing engine berhenti 
memproses otorisasi kartu — cascade 504 Timeout selama 32 menit.
Telemetri:
- Connection pool orders_db 100% saturated
- Deadlock antara process_recurring_subscriptions (batch) dan 
  process_live_checkout (real-time row locks)
- Thread dump: ratusan worker WAITING pada row-level table locks

[EXPECTATION]
1. 5-Whys Analysis — rantai kausal 5 level yang jelas.
2. Systemic Architectural Flaw — paragraf singkat tentang 
   lock ordering anti-pattern.
3. Remediation Plan terstruktur:
   - P0 (Hotfix immediate 24h)
   - P1 (Architectural refactor sprint ini)
   - P2 (Monitoring, alerting, chaos engineering)
4. Standar blameless post-mortem Google SRE.

⚠️ Kesalahan Umum RACE Framework

01

Flattery Fallacy

Memuji AI berlebihan ("jenius terhebat") tidak meningkatkan kualitas. Fokus pada domain dan metodologi.

02

Action Bloat

Menggabungkan terlalu banyak tugas dalam satu prompt. Pecah menjadi beberapa prompt fokus.

03

Context Starvation

Mengasumsikan AI tahu arsitektur internal Anda. Berikan konteks yang cukup — tapi jangan dump data.

04

Ekspektasi Ambigu

"Buat yang bagus" bukan ekspektasi. Definisikan format, panjang, tone, dan batasan negatif.

05

Fire-and-Forget

Mengharapkan hasil sempurna dari prompt pertama. RACE adalah fondasi — iterasi untuk menyempurnakan.

06

Tanpa Delimiter

Mencampur instruksi dengan data input tanpa pemisah. Gunakan header atau tag XML yang jelas.

Ringkasan — 5 Kunci Menguasai AI

01

Gunakan RACE Framework — Structure setiap prompt dengan Role, Action, Context, Expectation.

02

Engineer Context, bukan hanya Prompt — Rancang seluruh ekosistem informasi di sekitar model.

03

Kuasai teknik lanjutan — Chain of Thought, Few-Shot, dan System Prompt yang terstruktur.

04

Leverage Skills & Connectors — Kombinasikan skills modular dan hubungkan AI ke tools via MCP.

05

Tune parameter sesuai tugas — Low temperature untuk kode, tinggi untuk brainstorming.

Sekarang Anda punya semua bekal. Mulai praktik!
